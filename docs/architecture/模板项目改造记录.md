# 模板项目改造记录 v1.0

> 记录 food-ally 项目基于 `go-ddd-scaffold` 模板初始化时的架构调整，供模板仓库同步更新参考。

---

## 1. 改造背景

go-ddd-scaffold 模板提供了 DDD 六层骨架（domain → application → infrastructure → transport），但以下设计点在实际项目中需要调整：

| 问题 | 影响 |
|------|------|
| `internal/app/` 包名不符合 DDD 术语习惯 | 与经典 DDD 的 Application Layer 命名不一致 |
| 事件总线只有单层 Asynq 直连 | 无法区分进程内领域事件和跨进程集成事件 |
| 事件类型名全大写（`USER.REGISTERED`） | 不够语义化，无层次结构 |
| 领域事件+后台任务混在一个通道 | 概念混淆，后续扩展困难 |

## 3. 双层事件总线架构

### 4.1 问题诊断

模板原设计：
```
业务代码 → event.Publisher → AsynqEventBus.Publish → Asynq Redis
                                                         ↓
                                                   Worker → Dispatch → Handler
```

存在三个核心问题：

1. **Listener 订阅注册发生在 API 进程**，Worker 是独立进程，订阅关系丢失
2. **Domain Event 和 Asynq Task 概念混淆**——`ActivityLogListener` 既是领域事件消费者，又发布新的 Asynq Task
3. **无法支持一对多分发**——扫码完成事件需要触发评估、缓存、日记三个独立任务，当前只能串行

### 4.2 解决方案：双层模型

```
进程内领域事件                           跨进程集成事件
(Domain Events)                         (Integration Events)
─────────────────                       ─────────────────
events.DomainEvent 接口                  Asynq Task
events.Bus 接口（Publish/Subscribe）      messaging.EventBus（Worker 端）
InProcessBus 实现（sync.RWMutex）         AsynqEventBus 实现
仅依赖 domain 层                         依赖 Asynq + Redis
                                       ┌─────────────┐
业务代码 → InProcessBus → Bridge → Enqueue → Asynq Redis
              │                 ↓                  ↓
              │           queueMap 路由       Worker 消费
              ↓              ↓                  ↓
         进程内处理    critical/default   Listener/Handler
         (metrics等)                          ↓
                                         写 DB/发通知
```

### 4.3 核心文件

| 文件 | 说明 |
|------|------|
| `internal/domain/shared/events/domain_event.go` | DomainEvent 接口 + Bus 接口（进程内） |
| `internal/domain/shared/events/inprocess_bus.go` | InProcessBus 实现（sync.RWMutex 线程安全） |
| `internal/infra/messaging/bridge.go` | DomainToIntegrationBridge（领域→集成转换） |
| `internal/infra/messaging/event_bus.go` | TaskPublisher（简化版 Asynq 发布器） |

### 4.4 Bridge 路由配置

```go
func NewBridge(client *asynq.Client) *DomainToIntegrationBridge {
    return &DomainToIntegrationBridge{
        client: client,
        queueMap: map[string]string{
            "user.registered":      "default",
            "user.logged_in":       "default",
            "user.login_failed":    "critical",   // 安全事件→高优
            "user.account_locked":  "critical",
            // ... 新领域事件在此注册
        },
    }
}
```

### 4.5 应用层用法变更

**改动前**：注入 `event.Publisher`
```go
publisher := event.NewPublisher(eventBus)
authService := authentication.NewService(userRepo, tokenService, publisher, m)
```

**改动后**：注入 `events.Bus`
```go
inProcessBus := events.NewInProcessBus()
bridge := messaging.NewBridge(asynqClient)
bridge.SubscribeTo(inProcessBus)
authService := authentication.NewService(userRepo, tokenService, inProcessBus, m)
```

## 4. 事件命名规范

| 旧命名 | 新命名 | 规则 |
|--------|--------|------|
| `USER.REGISTERED` | `user.registered` | 小写 + 领域词.动词过去分词 |
| `AUTH.LOGIN.SUCCESS` | `user.logged_in` | 统一 user 前缀，撤回 AUTH 歧义 |
| `AUTH.LOGOUT` | `user.logged_out` | 同上 |
| `AUTH.TOKEN.REFRESHED` | `user.token_refreshed` | 同上 |
| `SECURITY.ACCOUNT.LOCKED` | `user.account_locked` | 同上 |

**约定**：`{领域}.{动作}_[状态]`
- 领域词：`user`, `family`, `food`, `scan`, `evaluation`, `diary`
- 动作/状态：过去分词或名词
- 全小写，用 `.` 分隔层级，用 `_` 分隔单词

### DomainEvent 接口

领域事件结构体需实现如下接口：

```go
// DomainEvent 接口定义（internal/domain/shared/events/domain_event.go）
type DomainEvent interface {
    EventName() string          // 事件名称，如 "user.registered"
    OccurredAt() time.Time      // 事件发生时间
}

// 领域事件实现示例
func (e *UserRegistered) EventName() string  { return "user.registered" }
func (e *UserRegistered) OccurredAt() time.Time { return e.Timestamp }

// 编译期断言
var _ events.DomainEvent = (*UserRegistered)(nil)
```

## 5. 数据库迁移治理

### 5.1 问题诊断

模板原设计存在双重建表冲突：

```
cmd/cli/main.go
├── db.AutoMigrate(&repository.UserPO{})   # GORM 自动建表（仅 UserPO）
└── executeSQLMigrations()                 # 手写执行 migrations/*.up.sql
```

| 问题 | 影响 |
|------|------|
| AutoMigrate + SQL 都在建 `users` 表 | 维护成本翻倍，改表结构需改两处 |
| 无迁移状态跟踪表 | 每次 `migrate up` 重复执行所有 SQL，非幂等 |
| 手写 `filepath.Glob` 依赖文件系统顺序 | `up` 方向未显式排序，执行顺序不可靠 |

### 5.2 解决方案：golang-migrate

模板原设计：
```
cmd/cli/main.go
├── gorm.Open + db.AutoMigrate(&UserPO{})  # GORM 参与 Schema 管理
├── executeSQLMigrations(up)               # 手写循环跑 SQL
├── executeSQLMigrations(down)             # 倒序循环跑 SQL
└── 无迁移版本跟踪
```

改造后：
```
cmd/cli/main.go
├── migrate.New(file://migrations, postgres://)   # golang-migrate 统一管理
├── m.Up()                                        # 顺序执行所有待处理迁移
├── m.Migrate(0)                                  # 回滚所有迁移到版本 0
├── m.Force(version)                              # 强制设定版本号
└── schema_migrations 表自动跟踪已执行迁移
```

### 5.3 核心变更

| 文件 | 操作 | 说明 |
|------|------|------|
| `cmd/cli/main.go` | 重写 | 移除 AutoMigrate 和手写 SQL 执行逻辑，替换为 golang-migrate |
| `go.mod` | +依赖 | 新增 `github.com/golang-migrate/migrate/v4`（含 `database/postgres`、`source/file` 子包） |
| `internal/infra/repository/user.go` | 不变 | `UserPO` 保留仅作为 GORM 持久化对象，不参与 Schema 管理 |

### 5.4 CLI 命令

```bash
# 正向迁移（执行所有待处理的 up 迁移）
cli migrate up

# 回滚所有迁移（到版本 0）
cli migrate down

# 强制设定版本号（已有数据库首次同步场景）
cli migrate force <version>   # 例：cli migrate force 11
```

### 5.5 设计原则

> GORM 仅作 ORM 工具使用，不参与 Schema 管理。所有表结构变更通过新增 SQL 迁移文件（如 `011_xxx.up.sql` / `011_xxx.down.sql`）管理。迁移文件命名需遵循 golang-migrate 规范：`{版本号}_{描述}.{方向}.sql`。

## 8. 字符串常量类型化

### 8.1 问题诊断

模板原设计所有字符串常量均为无类型别名：

```go
// 问题：编译期无法区分，任何 string 均可传入
const (
    EventUserRegistered            = "user.registered"    // 事件名
    QueueCritical                  = "critical"            // 队列名
    AsynqTaskSendVerificationEmail = "auth:send..."       // 任务类型
    ErrCodeUserNotFound            = "USER.NOT_FOUND"      // 错误码
)
```

| 问题 | 影响 |
|------|------|
| 常量无类型保护 | 函数参数接受 `string`，可误传任意内容 |
| 跨包引用脆弱 | bridge.go 中事件名硬编码为字符串字面量，拼写错误编译期不报 |
| 领域枚举裸露 | `RiskLevel`/`BarcodeType` 等 DB CHECK 约束值以裸 `string` 流通，无校验 |

### 8.2 解决方案：自定义类型别名

对所有字符串常量定义类型别名，编译期拦截非法赋值：

```go
// pkg/constants/constants.go — 基础设施级类型
type EventName    string   // 领域事件名称，如 "user.registered"
type QueueName    string   // 消息队列名称，如 "critical" / "default"
type AsynqTaskType string  // Asynq 任务类型，如 "auth:send_verification_email"

// pkg/errors/codes.go — 应用层类型
type ErrorCode string      // 应用错误码，如 "USER.NOT_FOUND"

// internal/domain/food/enums.go — 领域级枚举（方案A：领域内聚）
type RiskLevel            string   // green / yellow / red
type BarcodeType          string   // ean8 / ean13 / upc / upc_e / itf / qr / other
type SourceType           string   // user_contributed / manual / imported
type ContraindicationType string   // avoid / limit / caution / prefer
type SeverityLevel        string   // mild / moderate / severe / critical
type EvidenceLevel        string   // A / B / C / D
type IngredientUnit       string   // g / mg / μg
```

### 8.3 Bridge 路由类型化对比

**改动前**：
```go
type DomainToIntegrationBridge struct {
    queueMap map[string]string // eventName → asynq queue
    // ...
    queueMap: map[string]string{
        "user.registered":   "default",
        "food.item_scanned": "default",
    },
}
```

**改动后**：
```go
type DomainToIntegrationBridge struct {
    client   *asynq.Client
    queueMap map[constants.EventName]constants.QueueName
    // ...
    queueMap: map[constants.EventName]constants.QueueName{
        constants.EventUserRegistered:  constants.QueueDefault,
        constants.EventFoodItemScanned: constants.QueueDefault,
    },
}
```

### 8.4 文件变更

| 文件 | 变更 |
|------|------|
| `pkg/constants/constants.go` | 新增 `EventName` / `QueueName` / `AsynqTaskType` 三类型，8+3+6 个常量全部标注；修复 `ProjectName` / `RedisKeyPrefix` 为项目名称；新增 Food Redis Key 前缀 + 事件名常量 |
| `pkg/errors/codes.go` | 新增 `ErrorCode` 类型，20 个错误码全部标注 |
| `pkg/errors/errors.go` | `AppError.Code` `string` → `ErrorCode`，`NewAppError` 参数同步 |
| `internal/infra/messaging/bridge.go` | queueMap 改为 `map[EventName]QueueName`，字符串字面量全部替换为类型化常量引用 |
| `internal/domain/food/enums.go` | 新建，7 组领域枚举类型（严格对齐 DB CHECK 约束） |
| `cmd/api/main.go` | Swagger 标题 + 描述同步为项目名称 |

### 8.5 设计原则

> 所有字符串常量统一走类型别名 + 显式标注。基础设施级类型（`EventName` / `QueueName` / `AsynqTaskType` / `ErrorCode`）定义在 `pkg/constants` 和 `pkg/errors`；领域级枚举（`RiskLevel` / `BarcodeType` 等）定义在对应域包（`internal/domain/food/enums.go`），保持领域内聚。
>
> `DomainEvent.EventName()` 接口返回值保持 `string`（领域层不依赖基础设施包），桥接层做显式 `constants.EventName(eventName)` 转换。`AppError.Code` 字段同步升级为 `ErrorCode`，HTTP 响应层的 `Code` 字段保持 `string`（传输层不感知类型）。
